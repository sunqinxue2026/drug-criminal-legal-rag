# 法律 RAG 优化方案（精华版）

## 保留的核心思路

1. 知识库分层
- 法律规范层：法律法规、司法解释
- 裁判案例层：裁判文书、指导性案例
- 实务解释层：普法问答、面向普通人的解释材料

2. 文本切分按法律意义单元进行
- 法条、司法解释：按条切
- 裁判文书：按案件概览、事实、争议焦点、法院理由、裁判结果切
- 普法材料：按问答单元或主题切

3. 检索不是只做单次向量搜索
- 先理解用户问题
- 再做多路召回
- 最后按法律价值重排

4. 回答需要双视角
- 给律师：强调依据、裁判理由、程序与风险
- 给普通人：强调先做什么、证据、风险和下一步

## 去掉的部分

1. 不把“全文固定 500 字切块”作为默认方案
- 固定窗口只能做兜底，不适合作为法律场景主策略

2. 不把“只靠 embedding”当成高质量法律检索
- 法律场景需要结构、标签、程序类型和裁判角色共同参与排序

3. 不一开始强依赖外部商业数据库
- 北大法宝、无讼可以作为未来增强，不应成为当前系统落地的前置条件

4. 不把未标注来源的博客和 AI 自生成内容当核心知识库
- 只适合作为解释层补充，不作为裁判依据

## 当前已落地到项目的优化

1. 文书数据层
- 文书主信息、当事人、引用信息、检索切块已经分表
- 增加了律师阅读版正文、案件详情、纠纷概况、审理经过等字段

2. 切块层
- 生成案件概览块、裁判结果块、法律依据块
- 章节块按不同角色采用不同粒度
- 每个切块携带 sectionType、retrievalRole、sectionWeight

3. 检索层
- 新增查询理解模块
- 对口语问题做检索扩展，例如“我被人打了”会扩展到故意伤害、伤情鉴定、报警、赔偿等
- 使用多查询召回后再按元数据重排，而不是只看向量相似度

4. 生成层
- 普通人口语问题使用更偏实务和行动建议的回答模板
- 专业问题使用更偏依据和裁判思路的回答模板

## 下一步优化优先级

### P1：补齐权威知识源
- 接入现行有效法律法规
- 接入司法解释
- 为法条和司法解释建立独立的 chunk 与 metadata

### P2：做真正的混合检索
- 在现有向量检索基础上，增加 BM25 或全文检索
- 采用“关键词召回 + 向量召回 + 重排”的混合模式

### P3：专项规则
- 劳动、婚姻家庭、故意伤害、诈骗、执行、破产、知识产权分别建立专题规则
- 提升案由识别、程序类型识别和切块质量

### P4：评测体系
- 建立法律问答评测集
- 评估召回率、答案引用质量、法条命中率、类案相关性

### P5：前端可解释性
- 展示“为什么命中这些文书”
- 展示“法条依据 + 类案参考 + 风险提示”的来源路径

## 当前项目的推荐路线

1. 先用真实法律文书把“案例层”做好
2. 再补法条与司法解释，形成“规范层 + 案例层”
3. 最后增强混合检索和评测，作为答辩里的技术亮点
